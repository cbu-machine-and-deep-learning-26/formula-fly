# Security policy

## Supported versions

This repository is a course project under active development. Only the default
branch (`main`) and the integration branch (`develop`) receive security fixes.

## Reporting a vulnerability

Please **do not** open a public issue for vulnerabilities that expose secrets,
credentials, or a realistic path to abuse.

1. Use GitHub's **privately report a vulnerability** flow on this repository
   (`Security` → `Advisories` → `New repository advisory`), if enabled.
2. If private reporting is not enabled, open a minimal public issue titled
   "Security contact request" with no exploit details and wait for a maintainer
   to follow up.

Do not attach exploit proofs of concept, credentials, or private keys.

We will acknowledge reports as soon as a maintainer can respond and will
describe the fix or decline with a short reason.
